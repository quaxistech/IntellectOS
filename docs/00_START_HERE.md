# IntellectOS — единая документация проекта

**Дата согласования:** 2026-11-23. **Документальный профиль:** первая проектная версия (без фиктивных миграций). **Репозиторий:** `quaxistech/IntellectOS`, ветка **`main`**. **Статус:** проектная архитектура + верифицируемое описание текущих исходников, НЕ сертификат готовности к общему использованию.

## 1. Что создаём

IntellectOS — самостоятельная операционная система для широкого набора поддерживаемых компьютеров; Vibelang — её самостоятельный компилируемый язык `.vibe`; ИИ-компилятор — инструмент, предлагающий и проверяющий преобразования, а не исполнитель «промптов вместо машинного кода»; IVX-1 — проверяемый нативный формат `.ivx`, IntellectFS — собственная транзакционная CoW ФС. Нельзя смешивать эти продукты с Linux, GRUB, виртуальной машиной, cloud-agent или зависимостью от AI при boot/exec.

## 3. Приоритет документов и кода

1. **Истина о фактической реализации:** исходники `main` + прошедшие тесты и воспроизводимые журналы. Документ `15_CURRENT_IMPLEMENTATION` лишь датированный снимок; если код изменён, состояние нужно повторно проверить. Успешная сборка не доказывает работоспособность на железе.
2. **Продуктовая цель и обязательные решения:** 01, 02, 16. Конкретные ограничения важнее общих лозунгов.
3. **Бинарные форматы:** `specs/` задаёт точно определённые поля, только если их статус однозначен (`DRAFT`, `BOOT PROFILE`, `FROZEN`); объявление из кода не делает весь формат замороженным. Если есть противоречие между описанием цели и побайтовыми таблицами — не угадывать; фиксировать и разрешать через 19 до выпуска.
4. **Подсистемы:** 03–12; этапность и тесты: 13–14.
5. **История и исследования:** информируют дизайн, но не являются конкурентным текущим ТЗ.

## 4. Обязательное различие статусов

- **VISION:** пожелание/конечная цель; не реализовано автоматически.
- **DESIGN:** принцип утверждён, но контракт может быть неполным.
- **WIRE DRAFT:** байтовые поля предложены, однако нет независимого freeze.
- **BOOT PROFILE:** работающий узкий профиль, не полный стандарт.
- **IMPLEMENTED:** исходники присутствуют и компилируются в заданной среде.
- **TESTED/HOST:** функциональный тест на Ubuntu, с искусственным устройством или образом.
- **TESTED/QEMU:** реальный runtime QEMU/OVMF с логом и условиями.
- **OBSERVED/HARDWARE:** свидетельство на конкретном ПК; не универсальность.
- **RELEASED:** только после всех применимых gates из 14.

Никакой `PASS` в документе не назначается по факту наличия функции, картинки или теста без его успешного запуска.

## 5. Главный критерий установленной Terminal Edition

USB IntellectOS → выбор внутреннего диска и разделов → GPT/ESP + **IntellectFS** → проверяемые файлы ОС → самостоятельный UEFI boot с HDD/SSD после удаления USB → валидная конфигурация времени/пользователя → если установлен непустой пароль, корректный login; если пароль пустой — вход Enter либо политика автоматического входа → `init`/user manager → терминал из подписанного `.ivx` на IntellectFS в ring3. Критерий включает негативные сценарии, диагностику неподдерживаемого оборудования и восстановление при сбое.

Тот же продукт должен иметь голову без GUI (server/console), а позднее полноценный desktop. Отдельная модель Lenovo не определяет границы ОС; поддержка реально зависит от CPU ISA, прошивки и доступных драйверов. Никаких универсальных гарантий «на любом ПК» до матрицы оборудования.

## 6. Что делать с устаревшими документами

Старые файлы не удалены безвозвратно: оригинальные байты сохраняются в `research/` и `history/`, а Git оставляет их в истории коммитов. Исходный текст двух больших спецификаций переносится **без усечения** в `specs/`. Только перечисленные выше файлы в корне `docs/` действуют как актуальные. Не добавлять новые дорожные карты и «финальные версии» параллельно: редактировать владеющий раздел и обновлять реестр решений.
